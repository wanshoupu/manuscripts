\chapter{Loops} \label{ch:loops}

All major programming languages feature one or more loop types as control flow and
it is one of the most widely used building block.
Loop is a programing productivity amplifier---with a static loop body and
a scarce of overhead code (\textit{e.g.}, loop variables), the loop may be executed as many
times as needed.
But many developers often haphazardly stumble upon a first-working loop and settle.
Seldom anyone would try to think about the difference between the varieties of loops,
even fewer people would try different loop structures and loop types and see
which best fits the current situation.
This is so not because these developers have no appetite for better code.
A majority of them are not even aware that conscious choice of loop types and structures can make a
marked difference in the quality of code.
Therefore, I dedicate this chapter as a primer to the topic ``How to close your loop?''
and I meant it literally.

``Why!'' you say, ``What's the point for you to talk about loops as a language feature
outside of the language context?''
Yes, there are so much to say about loops in their generic sense.
Similar to the structure in ~\fullref{ch:organizeYourIfElse}, I will share mostly my first-hand
coding experience throughout the presentation of the chapter.
Beyond that, this chapter is also presented for completeness since
later discussions of the interactions between conditional statements and loop is built on
top of reader's mastery of loop programming.

\section{Loop anatomy}\label{sec:loopAnatomy}

This section is an overview of loop structures in a few programming languages of choice for
bookkeeping purposes.
\code{for}-loop and \code{while}-loop are the most common looping flow of control that almost all
languages support.
\code{do-while}-loop is a variation of \code{while}-loop that's supported by \java, \cpp, C, and
others but not \python.
We will begin with the generic structure of loops.
Although there are some variations, the basic constructs of a loop are the same.
\@\autoref{tbl:loop-construct} describes the generic parts of a loop in high-level languages.
\begin{table}[h]
    \begin{center}
        \caption{Function anatomy\label{tbl:loop-construct}}
        \begin{tabular}{l|p{10cm}}
            \hline
            construct & description \\
            \hline
            Pre-loop initialization &
            This is the preparation section in \code{for}-loop where variables declared there are
            usually hidden from subsequent code\footnote{This is is true for \java, \cpp, C,
            \textit{etc.}, but is not true for, \textit{e.g.}, bash}.
            Note that \code{while}-loop does not have a similar construct. \\
            Continuation condition &
            The condition for control to enter (or continue) the loop. \\
            Body &
            The block of statements to be executed in the loop. \\
            \code{break} statement &

            \code{continue} statement &

\section{Loop Design}\label{sec:LoopDesignConsideration}

From construction perspective, a loop is like an self-contained machine embedded in program.
Before the loop, effort is often spent to deliberately set up the machine.
At execution, the machine is triggered as control flows to it.
After control is yielded by it, output, if any, is collected for the rest of the program.

You can visualize a loop construct as a roulette, a carousel, or a Ferris wheel, all
three of which shares the properties of a circular sequence---an sequence with rotational
degree of freedom.
Even after everything has been laid out onboard, there is still the degree of
freedom of rotation as shown in ~\autoref{fig:loop-rotation}.
Thus, loop design involves arranging loop logic in the circular sequence and picking the
entrance and termination ports.
\begin{figure}[htb]
    \centering
    \includegraphics[width=.7\textwidth]{loop/ferris-wheel.jpg}
    \caption{Loop as a circular sequence.\label{fig:loop-rotation}}
\end{figure}
Depending on the location of the main loop condition checking statement, loops are roughly
classified as:
pre-condition loop, post-condition loop, mid-condition loop.
For programmer's convenience, programming languages frequently supports more than one types of
loops.
Depending on the entry point into the loop circular sequence and the programming language
of choice,
some loop construct is often more convenient than others.
Sometimes the termination condition checking is blended with the loop body with one or more
statement of \code{break} or \code{return}.
Other customization constructs are available in some programming languages such as
`\code{continue}' statement by which part of the loop body may be skipped.
\code{break}, \code{return}, and \code{continue} together with various loop constructs of
programming language of choice together satisfies majority of programming requirements (see
~\autoref{fig:fine-tune-loop-rotation}).
%TODO make figure
The best practice for loop design is to choose a loop construct
that is a closest match to your programming requirement so as to minimize loop customization.

These words may sound blurry and abstract to you.
So let us use examples to illustrate the ideas.
Say a particular bank allows customers to invest in stocks with their bank accounts.
The rule is that one is allowed to invest if and only if his balance is > zero.
Then for a particular account \code{accnt}, the program would look like
\begin{lstlisting}
    while(accnt.balance > 0) {
    accnt.invest();
    }
\end{lstlisting}

If the rule is changed such that one is allowed to invest if and only if his balance is > zero
\emph{or if the customer doesn't have investment history (hasn't invested before)}.
We would refactor the above code as
\begin{lstlisting}
    while(accnt.balance > 0 || accnt.investmentHistory == null) {
    accnt.invest();
    }
\end{lstlisting}
In either case, the pre-condition loop is the best fit.
For another example, we are to develop a command line tool that takes input from \code{stdin}.
The tool does a bunch of cool stuff with non-empty user inputs and terminates when user simply hits
`return' key (in which case input string length is zero).
Then the best loop construct for that would be mid-condition loop.
\begin{lstlisting}
    while(true) {
    str = stdin.read();
    if (str.isEmpty()) break;
    cool_stuff(str);
    }
\end{lstlisting}
For yet another example, a dice spinning game.
One is allowed to spin a dice $n$ times and the maximum number he got is used for subsequent move.
The most succinct code for that may be
\begin{lstlisting}
    maxSpin = 0
    do {
    maxSpin = max(maxSpin, spinDice());
    } while ();
\end{lstlisting}

There are some interesting aspects about for-loop.
The \code{<init>} is a statement to be executed only once before control enters the loop.
The \code{<condition>} may be regarded as the \emph{first} statement of loop body.
The \code{<condition>} are always executed one more time than the rest of loop body
unless there are break or continue statements inside.
The \code{<post-stmt>} is the \emph{last} statement of for-loop body.
and
The \code{<post-stmt>} is always executed as many times as the rest of loop body even when there
are \code{continue} in the loop body.
But when \code{break} statements are there, the \code{<post-stmt>} will be skipped.

\section{The `\textit{loop-and-a-half}' problem}\label{sec:loop-and-a-half-Problem}

``Why do we need the varieties of loops?'' you ask,
``Is there a one-size-fit-all loop?''

To answer this question, we need to start with research dated back 1966.
In 1966, Corrado B\"{o}hm and Giuseppe Jacopini proved that \code{goto} statements are
unnecessary and programs containing them can be transformed to use only conditional statements
and loops\cite{Bohm:1966}.
Along that line of thought, more researches which might have gone too far, attempted to remove
other `nuances' in computer programming such as \code{break} and \code{return} in the middle of a
loop to reduce control flow complexity and promote code composability.
But doing so are with prices.
More local variables are needed.
Even worse, it may require duplicate code before or after a loop.
This is the so-called ``Loop and a half problem''\cite{Louden-Lambert-2011}.

In summary, the \textit{loop-and-a-half} problem is the problem of partial code duplication of a
loop body caused by unnecessarily restricting in-between termination of a loop.
Variety of loop types are introduced to minimize the symptoms of the \textit{loop-and-a-half}
problem.
In the following sections, we will study how to programming techniques that alleviate
\textit{loop-and-a-half} problems with a few case studies.

\subsection{Linear stepping \textit{vs.} nonlinear stepping}\label{subsec:linearVs.NonlinearStepping}

When using a loop for simple step through, one usually steps through one element per round.
However this model does not work for all cases.
Sometimes one need to step through with a varying pace conditioned by the elements encountered
and this is what I called Nonlinear stepping.
Nonlinear stepping has an important application for simplifying logic within a loop.

\subsection{Sentinels to avoid condition checking}\label{subsec:sentinelsAvoidConditionChecking}

Often in a loop a number of cases are treated on a case-by-case basis and the termination case is
distinct from all others but poses as a symmetry breaking factor.

To have uniform treatment overall, one may introduce artifact, the `missing part' to complete
the pattern.

This artifact is called `sentinel'.
The benefit is
\begin{itemize}
    \item Avoidance of duplicate code
    \item Improved performance
\end{itemize}

\subsection{\code{do-while} loop to execute first loop without checking
condition}\label{subsec:do-while-loop}

\code{do-while} loop attempts to execute the loop body at least once no matter what because it
only checks the condition at the end of one round of loop execution.
This is useful sometimes to combine an initialization section with loop body.
Choosing pre-condition and post-condition loops is like choosing restaurants that charge
first versus ones that serve first.
If you are sure you you have enough money and you need a meal no matter what, you can go to a
restaurant that serves first.
But if you want to make sure you have enough money to pay for what you eat before you do it, you
should go to one that charges first.
