\chapter{Longest palindrome}

\section{The problem statement}

Given a string \code{S}, find the longest palindromic substring in \code{S}.

\section{Analysis of the algorithm}\label{sec:Manacher.algorithm}

Although algorithm is not the focus, you need a good understanding of it before moving on to the
rest of the chapter.
The optimal algorithm for detecting the longest palindromic substring in a string originates from
idea presented in a paper by Glenn Manacher~\cite{Manacher:1975}.
The basic idea originates from reflection symmetry in one-dimensional ($1$D) space,
\textit{a.k.a.}, mirror-image symmetry
\footnote{\url{https://en.wikipedia.org/wiki/Reflection_symmetry}}.
Let us firstly look at some aspect of the reflection symmetry.

As shown in \autoref{fig:a-axis-reflection-symmetry}, axis of symmetry $A$ partitions the entire $1$D
space into left half-space and right half-space about itself, and they are each other's mirror
image.
Axis $B$ does to the space similarly about itself \autoref{fig:b-axis-reflection-symmetry}.
If the two reflection symmetry axes are simultaneously present along the $x$-axis, by reflective
symmetry, infinitely many axes will be present and they will partition
the entire space periodically like magic, with a period
of $2d$ where $d$ is the distance between the two axes of symmetry
\autoref{fig:two-axes-reflection-symmetry}.
You may have experienced such an illusion by stepping into two parallel mirrors.
In reality, there is no infinite space.
But as long as there are overlapping visibility of each other's mirror image, you will
be able to experience this spectacular view to some extent.

The palindromic property of string is a manifestation of reflection symmetry as
\autoref{fig:palindrome-symmetry}.
It must be said that no space exists, neither does infinite string.
Nevertheless, the above pattern of periodicity still applies within certain bounds.

Note that the center of palindrome can be either a \code{char} in the string or between
two \code{char}s.
To facilitate coding and discussion, we treat the left end and right end of the string as two
special centers and the length of the palindromic substrings at these two centers are always zero.
Further, for empty string, the left and right ends collapse into the one.
So all included, there are $(2 * n + 1)$ possible centers, where $n$ is length of the string.
On any chosen center, the longest palindrome can be found by extending the left and right
boundaries as far as the equally distant pair of \code{char}s match.
As all the palindromes are thus found, nearby palindromes may overlap with one another---some
smaller palindromes may be nested within bigger palindromes.
Some interesting thing would happen if a \code{char} belongs to several palindromes at
once---reflective symmetries are catchy as they can be applied in sequence to produce hops,
double-hops, triple-hops, \textit{etc.}
All the reflection symmetries applied at once on one \code{char} would produce the same effect as
you stepping into a pair of parallel mirrors---a multitude of you are \emph{required} at
reflectively symmetric spots along the line.

This discussion of the reflection symmetry is very relevant to understand Manacher's
algorithm.

Take the string ``bananas'' as an example.
If one write down the palindrome lengths array for centers ordered
from left to right, one would get something like this:
[0, 1, 0, 1, 0, 3, 0, 5, 0, 3, 0, 1, 0, 1, 0]
Do you notice the symmetry? A long palindrome carries within its two wings shorter palindromes
that are total reflectively symmetric. So we can skip checking for some characters within the
right wing as we scan down the centers. In one loop, there are two frontiers: center and
rightmost checked char.

And this is indeed the case for palindromic substring.

For ease of implementation, we can map the original array to an augmented array by inserting
blank chars in between the chars in the original array and restrict the palindrome must be
centered on one of the element. So for "bananas", the augmented array would be
b a n a n a s

1. initialize an array lengths (lengths[0] = 1, lengths 1, 3, 5, will be mapped to lengths in original char as length / 2)
2 initialize a longCenter = 0, which records the center of the longest right-extending palindrome
3. for each char on position j in the augmented array,
if j lies within the right wing of the longCenter and the mirrored center, j', to the left of longCenter is trapped in longCenter's wing
record longest palindrome for c same as the j'
else
//get the length of the longest palindrome centered on j
for i = longCenter + lengths[longCenter] / 2 + 1; ; i++
if(2*j - i < 0 || i == 2 * n +1 || aug[2 * j - i] != aug[i]) {
lengths[j] = 2 * (i - j) + 1;
break;
}
end for
longCenter = j;
end if
end for

In the literature, there are several implementations already
published, for example the one of CS department of Princeton
University\footnote{\url{https://algs4.cs.princeton.edu/53substring/Manacher.java.html}}.

There the prescription of the algorithm was literally translated into code---the original string
ws preprocessed to fill with blanks.

But with a little maneuver, one can create a `virtual filling' among the characters of the
original string and save on physical memory footprint.
\autoref{lst:longest_palindromic_substring.py} and \autoref{lst:LongestPalindrom.java} are
implementations in \python and \java respectively based on string `virtual filling'.
