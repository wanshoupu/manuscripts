\chapter{Magic of Sentinels} \label{ch:sentinels}
Sentinels have been in use in military, mathematics, and civil engineering, long before computer
science became a science.
But it is computer science that made sentinels a prominent concept---a programming philosophy.
In this chapter we will consider sentinel values and the concept behind in a more general sense
than usual.
We will examine a few cases where uses of it lead to great simplification in coding.
%Sentinels are not deemed as part of control flow.

\section{Elephant in Cairo}\label{sec:elephant-in-cairo}

Have you heard of the infamous problem ``Elephant in Cairo''?
Behind the phrase is the fictitious programming question: ``How to hunt elephants in Africa?'',
first published in a magazine essay titled ``Pachydermic
Personnel Prediction'' ~\cite{elephant-in-Cairo:1989}
Even though it is fictitious, this question vividly illustrates the basics
behind sentinels and the important aspects of its usage.
%It explains the working of a sentinel very well.
The following algorithm is based on the original one outlined in the article but modified for
proper termination:
\begin{alisting}[H]
    \caption{\label{enum:elephant-hunt-algo-A}
    Algorithm for solving the `Elephant in Cairo' question.}
    \begin{enumerate}
        \item Go to Africa.
        \item Start at the Cape of Good Hope.
        \item Work northward in an orderly manner, traversing the continent alternately east and west.
        \item During each traverse pass,
        \begin{enumerate}
            \item Catch each animal seen.
            \item Compare each animal caught to a known elephant.
            \item Stop when a match is detected.
        \end{enumerate}
    \end{enumerate}
\end{alisting}
The above algorithm, however, may not end happily in the rare and
unfortunate case when there is no elephant in Africa and the hunters end up drowning in the
Mediterranean Sea.
To avoid that from happening, one may add a check before each traversal to ensure
that the north end of Africa has not been reached.


But an experienced computer scientist would place a known elephant
in Cairo before proceeding with elephant hunting.
And when he does, he uses ~\autoref{enum:elephant-hunt-algo-A} as is plus some
extra logic to do the post-hunting processing---they would have to inspect the animal they caught
and see if it is the one they placed.
They declare failure if it is and success if it is not.
Of course always remember to bring back home the sentinel elephant as a cleanup.


\section{Sentinel in General}

In the fictitious example above, the elephant placed beforehand is the `sentinel value'.
It serves as two roles.
One it guarantees that ~\autoref{enum:elephant-hunt-algo-A} terminates.
Second, it guarantees that an animal is at hand when ~\autoref{enum:elephant-hunt-algo-A}
terminates.
In doing so it helps save the unnecessarily in-loop checking for a termination condition.
Of course the onus is on programmer to check the animal to tell if it is the one placed or an
African elephant.
But the added benefit pays off this price.


This is a good starting point.
As I proceed deeper with my practices in software development, I realized that the concept
of sentinel can be generalized and it goes much beyond a mere saving on condition checking for
termination.
I summarized my applications of sentinels and listed the reasons I used sentinels as follows:
\begin{enumerate}
    \item\label{itm:sentinel:performance} Avoid costly condition-checking on performance-critical
    loops.
    \item\label{itm:sentinel:loop-and-a-half} Get rid of `Loop-and-a-half' issue
    as their research in Reference ~\cite{Louden-Lambert-2011}.
    \item\label{itm:sentinel:oddball} Avoid the `Oddball solution' smell~\cite{Fowler1999}
    \item\label{itm:sentinel:ds} Act as a padding boundary for data structures,
    such as linked list, \textit{etc}., to promote uniform operations.
    \item Added as a complementary part to fit a mathematical concept
    or to form a generalized algorithm.
\end{enumerate}


In all these cases, I found that \emph{fundamentally, sentinels are added to make the problem
more symmetric}.
Symmetry sometimes can seem mysterious to many and using it to explain this situation may cause
doubt in many.
%``What do you mean by `symmetric'?'' you ask dubiously.
Actually we can interpret `symmetry' as the mathematical language behind aesthetics.
Yes, symmetric objects are not only pretty but also saves human power to process.
Symmetric objects are visually pleasing because it has `order', is familiar to us.
Thus processing objects by our brain or by programs we built demand less energy.


On the opposite, asymmetric objects are irregular, anomalous, requires extra effort to process.
So symmetry represents uniformity, uniformity implies saving in resource.
From \code{for}-loops to regular expressions (regex), from HTTP response status
codes to \code{null} pointers, from recursion to dynamic programming, computer science is a
science that is constantly seeking or creating symmetric information to treat things uniformly,
to minimize energy footprint, and to do more with less.
Sentinels is no exception.

When we say ``It's one minute to 7'', we essentially made the representation of time more
symmetric and thus easier to understand.
What we meant is the following: first, put in one minute to make it
7 o'clock for more symmetric representation of time and then take away the minute to mean the
true time 6:59.


In the same way, sentinels does the pluses and minuses.
In the opening example `Elephant in Cairo', an elephant was added in the beginning and
deducted at the end.
In the examples that are to follow, more pluses and minuses will be performed.
They are all done for added symmetry.


Sentinels shift potentially costly operations from performance-critical
loop to non-critical section, from inconvenient location to convenient
location, and from many to one.
We can thus optimize our coding to be more elegant and performant.
In the following sections, we will have a brief look at a few applications of sentinels to
illustrate the fast application opportunities.

\section{String termination sentinels}\label{sec:stringTerminationSentinels}

Despite of controversial opinions\cite{Ritchie:1993,expensive-one-byte:2011}, the
null-terminated strings in C is another excellent example of sentinel use.
Even though saving memory is a major concern when it was originally designed, the
null-terminated string has many programming advantages.
One example is the expression \code{*p == '\0'} which test if the pointer \code{p} points to end
of the string.
Without using null character as a sentinel, it would not be so convenient to perform this test.
Null-terminated strings in other languages has been deprecated largely due to development
of containers and collections.
But the idea of it is still inspiring to us.
The following example will help illustrate this.
The problem statement is as follows ~\footnote{Credit to Leetcode\url{leetcode.com}}:
\begin{quote}
    Given a non-empty string s consisting of English letters and an abbreviation abbr,
    return whether the string matches with the given abbreviation.
    Abbreviation of word is given as replacing certain substring in the word with its length
    printed in decimal integer.
    \emph{Example 1:}
    Given s = "internationalization", abbr = "i12iz4n":
    Return true.
    \emph{Example 2:}
    Given s = "apple", abbr = "a2e":
    Return false.
\end{quote}
\begin{figure}
    \centering

So in other words, the tasks required for the problem is
\begin{enumerate}

    letter sections $L_{i}$ and number sections $N_{i}$, for $i = 1,2,\dots$
    \item\label{itm:parse.numbers} parse the number sections as integers
    as the number of letters to omit
    \item\label{itm:check.letters} Check if the letter sections, after skipping
    the corresponding number of letters, match corresponding sections in the word.
\end{enumerate}

One thing that is subtle and may slip your mind is that the letter sections and number
sections, while alternating, may have several cases to be considered (see
~\autoref{tab:letter-number-combination} for more information).

\section{Sentinels in Data Structures}\label{sec:sentinelsInDS}

Sentinel nodes have their niched uses in linked data structures such as linked list and tree.
The rationale behind this is explained below.
Linked data structures are fractured memory chunks, scattered all over the address space,
linked together only through connectors.
While they may have significant amount of nodes on boundaries,
algorithms for operations on these data structures are antagonistic to symmetry-breaking boundary
nodes.
Sentinel nodes are nodes that are spared for the purpose of freeing algorithms from having to
deal with boundary conditions.

One such example is the use of sentinel as an anchor node in algorithms concerning
singly linked list.
More aspects of linked list as a data structure

This deceivingly simple definition of a linked list conceals exceptional conditions

``What's so exceptional about it?'' you ask.

Some elaboration on sentinels.
The working of sentinels has physical analogy in nature.
The mechanism by which sentinel works is reminiscent to that of water vapor condensation, for
instance.
Water vapor condensation often takes place on the surface of something---
water bottle, stone, leaves, \textit{etc.}
Water vapor in the cloud also condenses on some non-gaseous core called `cloud condensation nuclei'
or CCN for short ~\cite{condensation:2005}.
Spontaneous condensation is possible but that has to overcome a huge energy barrier and
only takes place after spending hours in the so-called supersaturated state.
You see, even rainy day does not come easy without sentinels.
The vapor molecules need sentinels to usher them to where they should condense.
Also, catalysts, enzymes in biological organisms in particularly, work in a similar mechanism.
In light of quantum physics, catalysts and enzymes provide a bypass to an energy barrier,
a detour to the otherwise upheaval path for chemical reactions to take place while
their identities remain intact.
In this sense, it is not exaggerating to call sentinels the `catalysts for programming'.

\section{Boundary padding sentinels}\label{sec:boundaryPaddingSentinels}

So far into the chapter, you should have already gained understanding about sentinels.
Rather than let you go with the tiniest shade of doubt,
I decide to overexpose you to the instinct of sentinels with yet another example.
Sometimes sentinels are used as primer layer before the main treatment.
They are added to make the rest of the work easier.
In the example below, I am going to present a problem where using of sentinels simplifies the
algorithm.
The problem statement is as follows \footnote{Adapted from Leetcode \url{leetcode.com}.}
\begin{quote}
    Given a sorted integer array nums, where the range of elements are
    in the inclusive range [lower, upper], return its missing ranges.
    For example, given \code{[0, 1, 3, 50, 75]}, return \code{[2, (4,49), (51,74), (76,99)]}
\end{quote}
Note that the input integer array is sorted and non-decreasing.
Also, elements in the array lie within the range \code{lower} and \code{upper}, inclusive.

Here we are going to implement a `sweep-line' algorithm.
We are going to rely on a pivotal variable `\code{sweep}' initialized to \code{lower} at first.
It went through and repelled by the elements in the array.
For each element \code{e}, a range, $[\code{sweep}, \code{e}]$ (reduced to single point
\code{e} if \code{sweep == e}), is appended to the final result if valid.
This above process can potentially leave a final range unaccounted.
To complete algorithm, a post-loop check is needed to recover the final range (or single point).
The implementation is shown in ~\autoref{lst:missingRangeV1}.
\lstinputlisting[label={lst:missingRangeV1},
caption={An implementation for problem `Missing range'.}]
{sentinels/missing_range.py}
The above implementation has a mixed smell of `loop-and-a-half'
(see ~\autoref{sec:loop-and-a-half-Problem}) and `Oddball solution' problem\@\cite{Fowler1999}
and both are in the post-loop processing logic.
We say that it has `loop-and-a-half' smell because post-loop processing logic is disguised
duplication to the loop-body.
We say that it has `Oddball solution' because the post-loop logic is slightly altered version of
that in the loop-body.
All in all, the post-loop processing code poses itself as a nuisance.
Is there a way to get rid of it?

Yes!
Sentinel comes to rescue.
The post-loop logic is needed because of the possible residual range.
Can we add an extra element in the array so that it `reaps' the remaining range?
Along this line of thought, we can add a fictitious element `\code{upper + 1}' to the end of the
array.
This element won't cause any other effect except that it helps reap the possibly remaining range
after the last \emph{true} element.
The code is presented in ~\autoref{lst:missingRangeSentinel}.

the addition of sentinel element 'upper+1' in the array cuts off the cluttered
post-loop processing logic completely without any side effect.
Both of them are neat application of sentinel I have ever seen.
