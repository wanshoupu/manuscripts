    \begin{abstract}
        Quicksort algorithm with Hoare's partition scheme is traditionally implemented with
        nested loops.
        With Lomuto's partitioning scheme, the implementation is much simplified with one loop.
        However for certain edge cases, Lomuto's quicksort algorithm does not perform well.
        In this article, we present loop programming techniques and nested loop simplification
        processes that lead to simplified implementation for Hoare's quicksort algorithm which
        consists of a single loop.
        We believe that the techniques are beneficial for general programming and may be used for
        the discovery of more novel algorithms.
    \end{abstract}

    \section{Introduction}\label{sec:introduction}
    Loops are one of the most widely used programming constructs featured
    in almost all programming languages.
    A loop is an productivity amplifier.
    With nominal overheads (\textit{e.g.}, state-registering variables, \textit{etc.}),
    the static body of a loop can be reused for unlimited number of times.


    A key building block as loop, one would suppose its best practices should have been widely
    known.
    On the opposite, however, the best practices for loop are so largely ignored that it is not uncommon to spot
    haphazardly constructed loops with duplicate code dangling around even in production code.
    Obviously developers who authored the haphazardly `working' code were either oblivious
    with good programming practices or does not bother to spend the time on better loop constructs.

    Common problems programmers tend to make while programming with loops are
    \begin{itemize}
        \item Duplicate code
        \item Nested loops
        \item Leaky loop variables
        \item Heavy-duty initialization
    \end{itemize}

    Duplicate code between initialization and loop body or loop body and post-loop code
    is the biggest problem in loop programming and is the most common root causes for bugs.
    Duplicate code anywhere is bad.
    But duplicate code in and/or around loops is hard to realize and even harder to get rid of.


    The next commonly held misunderstanding about loop is the tendency to use nested loops.
    Many readers are ready to argue about this: ``What's wrong with nested loop?''
    The use of nested loops in many occasions seems to be reasonable, necessary,
    and at least harmless at first sight.
    But unfortunately this point of view does not stand for long.
    For almost all cases, nested loops bring complexity rather than convenience,
    obstruct readability rather than facilitating it.
    It turns what could have been coded as different components into monolithic mess and
    discourages code reusing.
    deepen the coupling rather than reducing it and discourage code reusability rather than encouraging it.


    Exposed loop variables are the third most common design problem in loop construction.
    This is essentially passing information from loop construct to subsequent programming units via
    the exposed variable(s) implicitly.
    It exposes implementation details of the loop and brings about entanglements among remotely
    related code, which is against the encapsulation principle.


    Oversize initialization is the fourth commonly found problem in loop programming.
    Since a loop may be considered as mini-programs and its state requires initialization.
    More often than not, with due skills and perseverance, the initialization may be achieved
    with a one-liner.
    However unskillful programmers may code disproportionally heavy initializations
    rather than light-weight, succinct ones.


    Addressing all these commonly programming problems is beyond what this article can do.
    So instead we will focus on duplicate code and nested loops.
    We will present two pillar loop programming techniques---`loop rotation' and `Nested loop
    thinning' which I found are effective in fighting against above programming foes.
    These are the two pillars for loop programming.
    Proper use of them help developers avoid commonly made mistakes.


    We have tried these techniques on case study, we will apply these programming techniques to
    simplify traditional quicksort algorithm to prove the effectiveness of these
    techniques---the implementation of quicksort algorithms.
    First invented in 1960, quicksort has been studied and analyzed well over the
    years\cite{Hoare1961,Hoare1962,sedgewick:1978,Bentley:1986:PP}.
    As one of the earliest `divide-n-conquer` algorithms, quicksort has become the \textit{de
    facto} sorting algorithm in practice for its excellent expected performance.
    Recently named one of the top $10$ algorithms of $20$th century, quicksort has a
    profound influence on the history of programming\cite{top10algorithm:2000}.


    We will walk you through the multi-stage refactor process that leads to the discovery of a
    brand-new implementation of Hoare's quicksort algorithm.
    We use Python as the working language in this article.

    \section{Conclusion}\label{sec:conclusion}
    In this article, we presented a couple of techniques for optimizing loop constructs.
    Taking advantage of the circular symmetry of loop constructs, loop rotation is applied to a
    loop to either reduce code duplication (forward rotation) or to prepare for mutation to another
    form (often reverse rotation).
    Another technique is loop thinning for simplifying nested loop complications.
    These are two of the empirical techniques that helps programmers achieve software development
    best practices.
    As an example, we applied these techniques in simplifying a traditional implementation of
    Hoare's quicksort algorithm.
    We provided the simplified implementation in C++.
    More generally, the programming techniques we developed in this article are applicable to all
    programming languages that supports loop and conditional constructs.
